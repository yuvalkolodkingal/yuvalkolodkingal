# Design principles for the terminal-style profile

These are the taste rules behind the style. Follow them and the result reads
as one deliberate piece; break them and it reads as a pile of widgets.

## 1. One metaphor, carried all the way through

The page is a shell session. Every section heading is a prompt with a
command that would plausibly print what follows:

```
### `yuval@github ~ $ whoami`
### `yuval@github ~ $ ./contributions.sh`
### `yuval@github ~ $ ls stack/`
### `yuval@github ~ $ git log --oneline`
### `yuval@github ~ $ cat projects.md`
### `yuval@github ~ $ exit`
```

Pick commands that match the content. `cat research.txt` prints prose;
`ls certifications/` lists things; `git log` shows recent activity; a
`whoami` is followed by a neofetch-style card. Do not mix metaphors (no
"About me" heading between two prompts) and do not overdo it (twelve
prompts on one page is a wall; six to nine is right).

The user and host in the prompt come from the config: `user` is the
person's short handle, `host` is `github` or their lab, company or project.

## 2. One palette, from one source

Every colour on the page comes from the theme. Headings, cursor and key
labels use the accent (blue by default). Body text is `fg`, secondary text
is `dim`, surfaces are `bg` with a `border` stroke. The other accents
(purple, teal, yellow, pink, green) each get one job: teal for the focus
line, yellow for the shipped project, purple for the snake and the poster,
pink only in the traffic-light dots. When every colour has a job, a reader
learns the code in a second.

Badge walls from shields.io break this because each badge brings its own
brand colour. If the person wants a stack section, render it as a panel in
the theme (`ls --color` listing, grouped) rather than thirty coloured pills.
If they insist on badges, keep them to one row and use a single style.

## 3. Self-contained, committed, generated

Nothing on the page depends on someone else's server at view time. Every
panel is an SVG generated by the engine and committed to the repository,
refreshed by the person's own GitHub Actions job. This is the reason the
profile never shows a broken image, never hits a rate limit and looks the
same in ten years.

The corollary: real data or none. Contributions, streaks, languages and
activity come from GitHub for the actual account, on a schedule. Never
type a number into a panel by hand; it will be wrong within a month.

## 4. Motion serves reading

Animation is there to draw the eye in the right order, not to entertain.

- Typing effects: at most one loop on the page (the header). Everything
  else plays once and freezes (the portrait, the info card rows sliding
  in) or moves slowly and predictably (the snake).
- Settle states: every animation ends or loops in a state that is the
  finished panel. A viewer who lands mid-cycle should still be able to
  read it.
- Stagger reveals by 40 to 60 ms per row so a card "prints" rather than
  pops, and keep the whole reveal under a second.
- Respect `prefers-reduced-motion` where the technique allows (CSS
  keyframes); keep SMIL motion gentle because it cannot be gated.
- Loops between 8 and 25 seconds. The snake is about 20.

## 5. Layout is a grid of cards

All full-width panels share one width (860 by default). Side-by-side panels
add up to it (370 + 490). Cards share the same corner radius, border and
title bar, so the page reads as windows on one desktop. Section order:

1. Header (who, in one typed line)
2. The one big number panel (contributions)
3. Who they are (portrait + info card)
4. What they use (stack)
5. What they are doing (activity, languages)
6. What they made (projects, research, writing)
7. Credentials (collapsed in `<details>`)
8. Contact
9. How this page is built (collapsed), and the exit line

Move sections if the person's story needs it (a researcher may want
research above projects) but keep header, whoami and contact where they
are: readers scan top for who and bottom for how to reach them.

## 6. Copy is short and specific

Panel text is written like terminal output: lowercase labels, no full
sentences inside cards, no exclamation marks. Prose sections (research,
projects) are two to four sentences each, in the first person, naming the
concrete thing (the product, the venue, the collaborator) rather than
adjectives. Delete "passionate", "enthusiast", "guru", "ninja" on sight.

Alt text describes the content ("Contribution graph for the last year,
with a snake eating its way across it"), never the format ("svg image").

## 7. The person decides what is true

The engine draws what the config says. The interview (in SKILL.md) is
where the agent learns what to put in: never invent a role, a location, a
project or a certificate. If a field is unknown, leave it out; a shorter
card with true rows beats a full card with guesses.

## 8. Signature motif

Every good profile has one thing that is unmistakably that person. Here
it is the ASCII portrait (a photo, or a DNA helix for a biologist, or a
circuit for an electrical engineer, or the logo of their project). Spend
the effort there, then keep everything else quiet so the motif carries.
